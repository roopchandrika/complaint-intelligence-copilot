
DRILL 1. SQL injection: string-building vs parameters
   User input: "x' OR '1'='1"

   UNSAFE (f-string). The SQL that reaches the server is:
   SELECT COUNT(*) AS n FROM dbo.TBL_CASE WHERE CO_NM = 'x' OR '1'='1'
   Rows matched: 50,000   <- the input became code: OR '1'='1' is always true

   SAFE (parameter). SQL text: ... WHERE CO_NM = :co   value sent separately
   Rows matched: 0   <- no company is literally named that

   Because the login is read-only, the unsafe query could only READ too much.
   With a write-capable login, the same mistake could delete data.
